# Head Chef coordination transport

Phase 4A uses one governed GitHub issue per owner question and machine-readable issue comments as the communication bus. The GitHub actor is the single owner-authenticated transport identity. Logical worker identity is derived from the exact coordination, assignment, expected event transition, fixed target worker/workstream pair, issue, and repository—not from a caller-supplied sender field.

This is logical role isolation under one owner-authenticated GitHub account. It is not evidence that six different human GitHub identities exist.

The workflow validates the triggering repository, owner, actor, issue, event schema, fixed role binding, canonical duplicate key, content hash, and immutable GitHub source readback. Before requesting OIDC, it fetches the exact Control Room question projection and independently validates the expected transition, assignment, worker, workstream, issue, and coordination identity. It performs a bounded retry only while an earlier prerequisite event may still be arriving. The authenticated Control Room POST then repeats transition and accepted-authority validation as the final write authority. Unrelated issue bodies and comments are ignored. Machine receipt comments are ignored to prevent recursion. Coordination events never commit research or publish specialist findings; the four existing trusted-team workflows remain the only specialist publication paths.

For every specialist assignment, the backend accepts one specialist result per review cycle and binds it to the assignment's exact accepted source IDs. A publication request, validated no-change result, or evidence blocker must reproduce the current result's decision class, sources, dependencies, and summary exactly. The append-only D1 constraints enforce those bindings atomically, so parallel comments cannot create two current results or close work from unassigned evidence.

The fixed Condition 4 assessment is a narrow exception to generic financial-word scanning because its factual rationale must name the accepted downstream PulseX swap and USDC token units. That exception requires the exact coordination, accepted Signals source, Worker #4/Investor pair, assignment projection, authorized outcome, and the complete byte-exact reviewed rationale (or the one byte-exact missing-record blocker template). The validator masks only that complete canonical passage, then applies the original full protected-action patterns to every remaining byte; appended financial, production, credential, authority, or execution instructions therefore remain rejected. An accepted publication receipt mismatch is retried only within the bounded transition window because the specialist pointer can briefly lag its workflow receipt.

Head Chef and Worker #5 have no specialist, identity-attribution, provider, portfolio, wallet, order, transaction, execution, or trading authority.
