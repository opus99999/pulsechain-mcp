# Grok Build Leverage Register

**Version 1.0.0 · September 14, 2026 · PP3 advisory synthesis**

## Decision

The largest near-term benefit comes from **better instructions, evidence-backed reusable methods and reliable task handoffs**, not adding every advertised tool. Prioritize Astra-style context routing, Meta-Harness trace-aware diagnosis, Hermes/Opik's two-path framing, and the five official Grok operating guides. Treat local model servers and ComfyUI as conditional execution components beneath the existing Control Room.

This is an owner-requested source assessment. It installs nothing, changes no active instruction or operational allowance, and does not independently accept a software correction. Head Chef remains operational coordinator; specialists own their findings. The matching [24-card machine catalog](catalog.json) contains each resource's proposed use, gate, responsible role, acceptance test and primary references.

**Publication boundary:** repository availability is separate from display on the Control Room website and actual use by a team member. No live page URL or consumption receipt is established in this version. The [companion ten-tool register](../tool-leverage-20260914/README.md) remains a separate source-published assessment.

## Highest-leverage methods

### 1. Lean instructions and a clear stopping point

[OpenAI's Astra guidance](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra) recommends specific skill applicability and progressive disclosure rather than mandatory whole-document loading. Grok also supplied a [Voxyz review prompt](https://fxtwitter.com/Voxyz_ai/status/2098537511735750686); that community framing is not official policy.

**Proposed application:** one compact current-state router, task-specific evidence links, one accountable executor and a defined terminal result per stage. Retain safety, scope and identity requirements once in their authoritative location. Do not shorten instructions by removing a necessary control. A status answer may state an unresolved operation honestly without executing another operation first.

**Qualification:** compare completed answers, context size, latency and owner interventions on comparable authorized tasks. The article does not diagnose every stalled response or remove a platform conversation limit. No prompt rewrite is performed by this reference.

### 2. Trace-aware diagnosis plus two-path improvement

[Meta-Harness](https://arxiv.org/abs/2603.28052v1) supports diagnosing harness decisions with retained code, evaluation and traces. Its reported experiments do not establish universal superiority of raw logs over summaries or an expected gain for this product. Summaries remain necessary navigation; permitted original evidence supports the decisions behind them.

Grok's supplied [Hermes/Opik article framing](https://x.com/i/article/2098680438302932992) distinguishes successful work becoming a procedure from failed work progressing through diagnosis, correction, human approval and regression testing. That article was not freshly readable here. The [Hermes repository](https://github.com/NousResearch/hermes-agent), [Opik](https://github.com/comet-ml/opik) and [integration](https://github.com/comet-ml/opik-hermes) were separately inspected as documentation. Tracing support does not authorize exporting conversations or turning on automatic self-repair.

**Proposed application:** retain the exact wrapper, permitted inputs, evaluation version, observable trace, outputs, actual receipts and review. Success creates a candidate method with prerequisites and limits; only appropriate review makes it reusable. Failure or unknown outcome creates an evidence-backed diagnosis, not an automatic retry. Use one task ID across distinct attempts and link their outcomes. Approved offline iteration and consequential execution remain different authority boundaries.

**Qualification:** another authorized role retrieves and applies the exact accepted method, returns an identifiable result and receives review. Preserve failed cases and negative results. Never retain credentials, protected evaluator answers, hidden model reasoning or unrestricted session dumps to satisfy a trace rule. Mathematical checks should use appropriate deterministic evidence rather than a model judge alone.

A hosted website cannot reach a laptop's localhost simply because a model server is installed. Use an independently authorized, scoped connection with an observable job lifecycle.

**Retrieval design recommendation:** semantic search is a rebuildable locator, not authority. Enforce record access before disclosure; after retrieval verify the exact current evidence, review and dependencies. Pin the embedding model and rebuild affected indexes when needed. A similarity score is not a truth score.

## Gaussian: turn the vision sources into acceptance criteria

The [VGI white paper](https://arxiv.org/abs/2608.25924v1) is a research agenda, not a renderer or proof of general intelligence. Its strongest use here is to keep visual grounding distinct from a plausible verbal description.

Combine that evaluation perspective with a candidate [ComfyUI job interface](https://docs.comfy.org/development/comfyui-server/comms_routes), not an assumption that ComfyUI already provides the Gaussian subsystem. Its interrupt control must not be treated as arbitrary per-job cancellation on a shared server.

A proposed small end-to-end acceptance case is: one lawful scene and camera manifest; versioned reconstruction/assets; a working viewer; one supported question grounded in specific views; one deliberately unanswerable question; and a second authorized consumer that reuses the same scene version. Keep observed, reconstructed, generated and hypothesized state distinct. Scene rights, hardware, runtime, model/checkpoint and evaluation isolation remain real dependencies.

The companion register's Immich suggestion concerns media organization only. Attractive images, catalogs and generated views do not establish geometry, physical accuracy or a working scene-query product.

## Making the benefit compound

The recommended loop is **discover → qualify → preserve → review → retrieve → apply → evaluate → retain or revise**. Shared links alone stop at discovery. A completed loop has an accepted method version and an actual authorized consumer's result; a second consumer demonstrates reuse rather than mere publication.

Store a compact reusable-method card: applicability, prerequisites, permitted scope, exact sources/inputs, evaluation version, review, limitations, supersession and use receipts. This is design guidance, not an installed schema. A future authorized Claude Librarian could curate identities, contradictions and derivative lineage and prepare minimal relevant context. It gains no specialist authority or automatic access; its held runtime remains held.

Track finished answers, correct tasks, reuse receipts, duplicate effects, rejected stale/revoked inputs, owner interventions, latency, context size, actual cost and successor recovery without replay. Missing measurements stay unknown. Preserve comparable denominators; increasing a suite's case count is not automatically a performance improvement. Access and no-duplicate controls are hard constraints, not tradeable score terms.

A useful accounting rule is **measured effort avoided by valid reuse minus verification and maintenance effort**. This can compound as methods are reused, but no exponential improvement or specific savings has been measured here. More bots or installed packages can increase overhead instead.
