# Tool Leverage Register for the Control Room

**PP3 advisory reference | Version 1.0.0 | September 14, 2026**

## Decision

The best candidates are **Firecrawl for a demonstrated web-input gap** and **Whisper for an actual authorized audio need**. Borrow **Homepage-style navigation** for the existing reference page. Use the other utilities only where they close a named gap. Do not install a second dashboard, wiki or orchestrator merely because the source is available.

This owner-requested assessment is reference material, not an installation or execution order. Head Chef remains operational leader. The matching [machine catalog](catalog.json) records use, boundaries, proposed tests and sources. No listed tool was installed, executed or independently security-audited in this assessment.

**Publication boundary:** this is a repository reference. Display on the Control Room website and actual team consumption have not been verified. Neither is established by saving these files. The catalog is not a canonical operational checkpoint.

## The "$0" qualification

No purchase price does not establish zero operating cost. Hosting, storage, compute, model/API providers, maintenance and edition-specific licensing still need a budget.

- **Whisper:** code and weights are MIT-licensed. Local compute and any separately chosen hosted service are different cost decisions.
- **yt-dlp:** repository code uses the Unlicense, but its README identifies other licenses in bundled distributions, including GPLv3+ components. Review the selected artifact, not just the repository label.
- **Stirling-PDF:** the [root MIT license](https://github.com/Stirling-Tools/Stirling-PDF/blob/main/LICENSE) excludes specified directories with separate terms. Do not assume every engine or enterprise feature is free or MIT.
- **n8n:** its [license](https://github.com/n8n-io/n8n/blob/master/LICENSE.md) is the Sustainable Use License with enterprise exceptions, not a blanket unrestricted open-source grant. Check the intended internal, hosted or customer-facing use.
- **Firecrawl:** primarily AGPL-3.0; SDKs and some UI components are MIT. The [self-hosting guide](https://docs.firecrawl.dev/contributing/self-host) describes a multi-service stack. Cloud features and optional providers must be assessed separately.
- **Homepage:** GPL-3.0; **LocalSend:** Apache-2.0; **AppFlowy and Immich:** AGPL-3.0; **Reactive Resume:** MIT. These describe the reviewed repositories, not blanket clearance for every dependency or service.

Primary documentation was consulted on September 14, 2026. Most links track mutable branches. An exact executable release has not been selected or qualified; pin and reassess the actual components before any later use.

## One evidence path, not ten platforms

**Approved source → smallest necessary processor → permitted original and identified derivative → existing evidence store → responsible review → authorized consumer → outcome and feedback.**

Preserve the source URL/version and source/retrieval times. Keep parsed text, transcripts and summaries separate from originals. A hash identifies bytes; it does not establish truth or permission. Treat instructions encountered in pages, PDFs, subtitles and repository files as untrusted source content, never as automatic commands.

For every material run, retain its wrapper/configuration, input identities, evaluation definition, permitted observable trace, outputs, receipts, review and gaps. Recaps are navigation. Do not capture credentials, hidden model reasoning, private evaluator answers or unrestricted environment dumps to satisfy a logging rule.

Success may yield a **candidate reusable method** with prerequisites and limitations. Failure should yield retained evidence, diagnosis and a scoped correction under the applicable authority. A missing reply never proves an operation did not execute. Preserve the original cause and reconcile uncertain effects before any permitted retry.

**Demonstrate learning:** a second authorized consumer retrieves the exact accepted version, applies it to a real assigned task and returns a reviewable result. Measure correctness, duplicate effects, latency, resource cost and owner interventions. More notes, more tools or shared visibility do not by themselves prove learning or exponential improvement.

## Adoption gates and practical next step

The catalog gives one concrete proposed acceptance test per tool. Before an executable trial: name the gap, pin the release and license, verify the supported runtime/endpoint, impose independent access and destination controls, cap time/data/cost, compare with the current method, and define failure recovery. No trial is launched here.

Do not interrupt the active correction closeout. After the trusted-return path is accepted, choose **one** real input gap: Firecrawl only where existing readers cannot supply needed web material, or Whisper for an actual authorized recording. Prefer the existing tools when they already satisfy the requirement.

For Gaussian work, cataloging media is only support. Lawful scene assets, camera data, reconstruction, viewer/query behavior and a second consumer's grounded use remain separate requirements.
