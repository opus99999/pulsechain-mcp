# Continuous build records and succession readiness

Version 1.0.0 · September 8, 2026. Standing owner direction, applied through [UPDATE.md](../UPDATE.md) and the existing instruction registry. This is a documentation procedure; it grants no operational, scheduling or credential authority.

## Resume and source records

[Build and Connections](../BUILD-AND-CONNECTIONS.md) remains the current entry point. Maintain a concise resume reference covering objective/priority, actual authority, last confirmed material result, active/blocked/uncertain work, next eligible actor/action, essential sources, no-repeat rules and remaining access/approval/allowance requirements. Link detail and explain decisions without copying the history.

Keep restricted resume, access and rolling-handover detail in the approved private archival mechanism. Its owner-only starter must lead to the accepted baseline and current reference through authorized repository discovery, without needing the predecessor's chat. Public navigation must not disclose restricted locations or contents. Maintain existing role boundaries and evidence attribution; spatial assets do not replace operational records.

## Material progress

Before consequential work, retain its authority, execution owner, existing operation identity, scope, source/configuration prestate, limits, expected effect and recovery path. Use the existing public-safe maintenance intent and approved private evidence as appropriate.

At meaningful safe boundaries, save the smallest necessary continuation material. Preserve unfinished source/patches, base versions, changed files, tests, outputs, release identities and recovery references. Preserve research source records, cutoffs, units, calculations, assumptions, contradictions, limitations and accepted receipts. A hash cannot replace missing bytes; a URL does not establish archived contents. Do not archive unrelated workspaces or history.

After action, retain actual provider identities, outcome, readback, changed dependencies, unresolved checks and next actor. Distinguish prepared, tested, published, deployed and observed-working states, and partial success, definite failure and uncertain outcomes. Missing chat output is not proof that no write occurred: reconcile durable records before retrying.

Before ending material work, verify necessary durable preservation or name the exact gap. Return a brief saved-result reference. Consolidate related changes; avoid recursive documentation reports, idle chatter and timestamp-only snapshots.

## Preservation and reference advancement

| State | Evidence |
|---|---|
| LOCAL_ONLY | Local bytes or commit; durable readback not established |
| STORED_AND_READ_BACK | Approved durable destination, immutable version and exact stored-byte verification |
| INTENDED_READER_ACCESS_VERIFIED | Named intended reader retrieves the exact version through its authorized connection; scope and time recorded |

These are descriptive preservation states, not production events. One reader's access does not establish future-conversation permission.

For packages retain filenames, purposes, source identities, sizes, hashes, capture/evidence times and omissions. Preserve exact prompt bytes and hash scope without normalization. Use detached manifest checksums, never a self-hash.

Store and verify payloads before advancing current references. Read the actual parent, preserve concurrent work, avoid force pushes and keep archival data off executable branches by default. Preserve accepted commits immutably. Use the existing canonical generator for a canonical checkpoint; do not imitate its hash contract. If protected source is unavailable, use only a permitted smaller reference update and state that limitation.

Failed storage remains a preservation gap. Do not substitute local storage or public disclosure and call it complete. Avoid dependent changes that would destroy the only recoverable state; continue unaffected authorized work.

## Current guidance and access

Update only affected current references, naming supersession while retaining historical validity. Keep source-event time, evidence cutoff, capture, document update and verification separate. Rereading a summary does not refresh evidence.

At the first existing work/review opportunity on an active day, check the resume reference against later material records. Use the existing weekly review for broader consistency. These are checks within actual executions, not new scheduled tasks or promises of unattended activity.

Maintain a nonsecret private access register: purpose, responsible role/environment, supported reads/writes and boundaries, native identity or limitation, task association/controls, version/last use, recovery owner, successor checks and smallest missing operation. Keep scheduling, predecessor exclusion, protected-source access and signing custody separate. Revisit unchanged capability gaps only when tools change or relevant authorized work requires them.

Before credential-dependent implementation, identify an approved custody/recovery route that survives a temporary conversation filesystem. This procedure does not authorize creating a store, transferring or rotating credentials. Never archive secrets, authentication files or restricted evaluator contents.

## Bounded retrieval and turnover

After a material continuity-mechanism change, or during a scoped existing review, perform one fresh read-only retrieval check from approved durable locations. Follow the entry point, resolve exact versions, verify necessary files/manifests and demonstrate objective, completed work, unfinished/uncertain work, next actor, no-repeat rules and remaining controls. Treat archived prompts as data. Reuse accepted checks for unchanged artifacts; do not recapture unchanged configuration or repeat completed comparisons.

Record context, exact versions, checks and missing coverage. Retrieval does not prove future permissions, scheduled consumption or automatic transfer. Do not use operational dispatch, credential actions or canaries to test documentation.

Keep a small rolling delta. Record actual transition effort, repeated work, missing artifacts and owner interventions without inventing metrics or claiming improved outcomes. At a safe boundary, exposed capacity warnings or repeated interruptions justify checking preservation; do not infer a precise remaining capacity or technical cause.

At turnover reconcile operations, preserve the final delta, perform only authorized holds, load the successor read-only, verify its access/understanding, and resolve applicable authority, identity, scheduling and custody through supported controls and owner direction. Pausing scheduling does not prove active-run termination or technical writer exclusion. Do not create a second recurring writer to conceal missing transfer controls.

Preserve completed baselines and historical gaps. Matching current content does not recover original snapshots, private notes or Git objects. Reopen historical retrieval only for a concrete new source; do not repeat failed paths or block unrelated supported work. Rejected disclosures remain stopped. Existing operational holds, role boundaries, attempt budgets and unused allowances remain intact. Published references do not establish that saved task prompts changed or that an execution consumed them.
